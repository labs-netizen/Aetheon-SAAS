# MODULE: Alert & Notification Hub

- **Status**:
  - Alert Persistence & Retrieval: `VERIFIED_LOCAL`
  - Alert Acknowledgment & Immutable Audit: `VERIFIED_LOCAL`
  - Automated Condition Generation Engine: `NOT_IMPLEMENTED` (Manual trigger / API-driven in V1)
  - Outbound Email Delivery: `PRODUCTION_CONFIG_REQUIRED` (Mailpit/Inbucket `:15434` for local auth; production SMTP/SES not configured)
- **Authoritative UI**: `src/app/alerts/page.tsx`
- **Authoritative API**: `src/app/api/alerts/route.ts`, `src/app/api/alerts/[id]/acknowledge/route.ts`
- **Auth/Entitlement**: Viewing requires site access or org-wide view. Acknowledgment requires `OPERATOR`, `ENERGY_MANAGER`, or `ORGANISATION_ADMIN`.
- **Reads**: `alerts`, `notification_logs`.
- **Writes**: `alerts` (update acknowledged status), `audit_logs` (immutable audit record).
- **RPCs**: `acknowledge_alert_atomic(alert_id, user_id, user_role, org_id)` (Migration 13 atomic update + audit log).
- **External Service**: Local Supabase Inbucket (`:15434`) for local auth verification emails only.
- **Quality Gate**: Direct database update rejected; acknowledgment must pass through atomic security-definer RPC.
- **Fail-Closed Conditions**: Acknowledgment fails safely; UI state updates only after server returns HTTP 200. Notification log privacy RLS prevents non-admin users from reading other users' alerts.
- **Provenance**: Records acknowledging user, role, and ISO timestamp atomically in `audit_logs`.
- **Reports**: Alert records queried by ID/site.
- **Alerts**: Schema defines canonical alert categories: `PEAK_DEMAND_WARNING`, `DSM_HIGH_RISK_DEVIATION`, `BESS_SAFETY_LOCKOUT`, `COMPLIANCE_DEADLINE_WARNING`, `RENEWABLE_UNDERPERFORMANCE`, `DATA_PIPELINE_STALE`. Note: Automated background condition evaluator is `NOT_IMPLEMENTED` in V1; alerts are persisted records.
- **Demo Behavior**: Interactive alerts feed with simulated acknowledgment.
- **Live Behavior**: Real database updates in `alerts` and atomic `ALERT_ACKNOWLEDGED` entries in `audit_logs`.
- **Tests**: `tests/integration/adversarial_api.test.ts` (Test 21), `tests/e2e/demo_smoke.spec.ts` (Test 8), `tests/e2e/real_auth_workflows.spec.ts` (Test 6).
- **External Requirements**: Production transactional email provider (SendGrid, AWS SES, or Resend) required for outbound email delivery.
- **Known Limitations**: Automated condition evaluation pipeline and SMS/WhatsApp dispatch are not implemented in V1.
